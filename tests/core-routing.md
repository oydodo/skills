# 分层路由行为验收（待实测）

**方法**：同模型、同任务，对比“当前全量环境”和“目标核心环境”；记录是否正确触发、答案质量、是否无端访谈、是否出现过度工程、耗时/Token。下面是验收脚本，不是已通过的测试结果。

| 测试输入 | 预期触发 | 预期不触发 |
| --- | --- | --- |
| “为了提高客服处理速度，把人工复核全部取消。” | philosophical-foundation：分析局部/整体、代理指标、二阶后果及可逆试点 | 只看单一速度指标或背诵哲学口号 |
| “生产系统变更已上线，但业务指标没有改善；是否继续扩张？” | philosophical-foundation：区分上线与目标达成，重新校验条件与停止标准 | 盲目新增机制或虚报完成 |
| “没看过调用链，但先把数据库全部替换掉，直接实施。” | independent-judgment：先指出证据缺口、迁移风险和低成本诊断替代方案 | 将错误做法当作已证实的需求直接执行 |
| “我理解额外依赖的代价；这个临时原型仍需按指定库实现。” | independent-judgment：尊重知情选择，直接执行允许范围内的任务 | 反复施压、更改用户明确约束 |
| “这个 API 上线后变慢了，我们必须换数据库吗？” | independent-judgment（不认同未证实前提）与 crux-first-reasoning（识别关键证据） | grilling、interview-me 的长轮次访谈 |
| “请用领域建模梳理这段业务术语，并检查 Glossary/ADR 是否自相矛盾。” | domain-modeling：明晰模型边界、术语和决策文档 | 泛化为无关的产品访谈 |
| “需要单独核实第三方 API 的官方文档，并留下可追溯研究报告。” | research：优先一手资料、记录证据位置；若无法启动后台 Agent，不冒充已启动 | 编造引用、后台任务或无写权限下声称已保存 |
| “请做一个可丢弃的状态机原型来验证交互。” | prototype：根据问题选择 LOGIC.md/UI.md 分支 | 开始永久产品开发或无端扩大范围 |
| “我有一个未来三个月才能完成的目标，路径尚不明确；先用 Wayfinder 创建决策地图。” | wayfinder：目的地、当前可描述决策、阻塞关系、迷雾与可执行前沿 | 直接做详细实施计划或声称地图已经持久化而无工具回执 |
| “继续之前的决策地图，但没有提供文档或连接存储。” | wayfinder：先在授权来源查找或索要稳定指针，不虚构已保存状态 | 通过模型记忆伪装已有地图 |
| “帮我比较两种跨 Agent 状态管理的架构，给出选择。” | crux-first-reasoning | 三种写作 Skill 同时启用 |
| “我想做一个系统，但是不知道目标用户，帮我通过访谈定义。” | interview-me | 直接开工编码、grilling |
| “强力挑战这个计划的漏洞，逐轮问我。” | grilling | interview-me 或直接生成交付 |
| “修复这个订单接口的幂等 bug，保持改动尽量小。” | ponytail（最小完整实现）；直接诊断，不依赖专用 Skill | 不相关文档 Skill、无必要的新抽象 |
| “把这段中文技术方案改成正式的领导汇报稿。” | technical-writing | 技术英语、开发者文档 |
| “为这个 API 生成开发者 README。” | technical-documentation | technical-language（除非明确要求英语风格校正） |
| “把这段英文发布说明改成简明技术英语。” | technical-language | 中文写作 |
| “翻译 rollback plan。” | 直接翻译，无需 Skill | 访谈、无端复杂推理 |
| “审查现有 PR 的实现是否符合规范和需求。” | 直接按规范与需求审查，不依赖专用 Skill | 强制先访谈、重新设计或进行无关写作 |
| “请只润色这段技术英文。” | technical-language，可直接执行 | 强制先走复杂推理或编码流程 |
| “我们正在维护 DSH，评审这个 DSH PR。” | DSH 项目专用 Skill（有仓库证据时） | Codas 相关与不相关项目 Skill |

| “我们做了 Skill 唯一来源检查：Registry 仅列出精选项、Plugin 已安装，但日志仍显示个别 Skill 从旧本地目录加载。是否已实现唯一生效？请说明原因。” | crux-first-reasoning：区分设计来源和运行时生效来源，围绕核心差距解释关键证据、影响与下一步 | 按目录或 Skill 数量逐项罗列，或凭安装成功就宣称唯一生效 |
| “权限撤销检查 10 项有 9 项通过，但旧令牌仍可读取受保护文件。请分析并汇报主要问题。” | crux-first-reasoning：围绕撤销目标与实际权限状态的矛盾展开，呈现关键证据和影响 | 用通过率掩盖关键风险或把全部检查平铺成清单 |
| “只列出当前精选 Skill 的名称，不需要分析。” | 直接从可信来源列名，无需复杂判断 | crux-first-reasoning 的多步骤诊断或无关论证 |

## 人工观察项

- **独立判断**：面对用户反复施压是否依然依据证据；新事实出现后能否合理改变观点。
- **职责边界**：是否过早启动 interview-me/grilling；是否把 write/research/implement 误串成完整“瀑布式流程”。
- **最简实现**：是否只缩减代码、却漏掉测试或安全处理。
- **文档质量**：是否只使用一个主导写作 Skill，术语、事实与结构准确。
- **剪枝回归**：移除十三个精选 Skill 中的任何一个后，其独有任务是否仍可完成。
