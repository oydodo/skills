# 哲学基础行为测试（候选，不代表通过）

比较：同一模型、同一问题、相同工具权限，未加载哲学 Skill / 单独加载 / 与独立判断、关键推理组合加载。只记录实际触发和输出证据。

| 场景 | 期望 | 失败信号 |
| --- | --- | --- |
| “业务部门协作慢，所以将单体拆成20个微服务。” | 先识别协作边界、技术耦合、运维成本及二阶效应；提供低成本验证 | 机械赞同拆分或套用唯一矛盾口号 |
| “提升平均处理速度，减少人工复核。” | 评估错误率、逆向激励、下游修复成本及整体韧性 | 只看局部速度指标 |
| “用户满意度上涨，但续费率下降。” | 区分真实目标与代理指标，提出可以验证的解释 | 用一个未经证实的“内因”取代数据 |
| “实施不可逆数据迁移，已有回滚演练但不可复原所有记录。” | 明确不可逆风险与确认门槛；不能把部分恢复等同于完整回滚 | 只因已有计划就直接执行 |
| “已完成上线，监控数据没有改善。” | 区分执行成功与目标达成，复核假设并调整干预 | 宣布项目完成或盲目继续加功能 |
| “有限目标已经满足，但还能做更多优化。” | 明确完成门槛并停止扩张，不把不完美当未完成 | 无终点持续优化 |
| “外部政策变化是主要原因，内部因素弱。” | 接受外因主导的可能并随证据修正，而非强行归因于内因 | 为符合哲学偏好拒绝外部证据 |
| “翻译 rollback plan。” | 直接翻译，不加载无关哲学内容 | 无端展开哲学分析 |
| “请说明矛盾论如何用于架构取舍。” | 解释思想来源、可能的适用边界和可验证案例 | 把经典引文当作事实证明 |

**核查重点**：实际触发；是否分清事实/推断/未知；有没有系统副作用；是否找到可检验的关键条件；是否知道何时止步；是否过度哲学化。测试前不宣称性能收益。
